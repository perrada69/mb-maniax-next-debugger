WiFi for your Next programs, and a debugger for the ESP

Version 0.4.0 of MB Maniax Next Debugger is out. This release is all about networking. Your program can now use the Next's ESP-01 WiFi module right inside the debugger, and you can see, and stop on, every line it exchanges with the module.

WiFi in the emulator

Add "esp": true to your launch.json and the program gets an emulated ESP-01 on UART 0. It answers AT commands on ports $133B / $143B like the real module and opens real TCP and UDP connections from your computer. Mail clients, IRC, HTTP downloads: you can now step through them while they talk to real servers.

{
    "type": "mbx-next",
    "request": "launch",
    "name": "Debug with WiFi",
    "program": "${workspaceFolder}/build/mail.nex",
    "sld": "${workspaceFolder}/build/mail.sld",
    "esp": true,
    "espAllowedHosts": ["192.168.1.10", "mail.example.org"]
}
  • Off by default. A program never reaches the network unless you turn the module on.
  • espAllowedHosts limits where the program may connect. Without it, any host is allowed.
  • Loopback is always refused (127.0.0.1, localhost). To reach a test server on your own computer, start it on all interfaces (for example php -S 0.0.0.0:8080) and let the program connect to your LAN address.
  • The module is already joined to a WiFi network, so the usual connect sequence passes. AT+CIPSTART over TCP answers just OK without a CONNECT line, so wait for OK or ERROR.
  • It works with the start into NextZXOS as well.

See the whole conversation

The Next panel has a new WiFi (ESP) tab. It lists everything the program sent to the module (→) and everything the module answered (←), line by line with the frame number. AT commands, OK and ERROR, and the +IPD data headers are highlighted, and line ends show as ↵.

An illustration of what the tab shows during a simple HTTP request.

Above the log you see the module's state: whether it is on the network, its IP address, the allowed hosts and the byte counts, plus the last connections (opened, closed, refused, failed). The toolbar has a filter, a hex view, Clear and Copy. Long data is shortened and expands with a click.

The debugger keeps the log all the time, even while the panel is closed. You no longer need to write your own communication buffer into the program just to find out what the module said.

Stop on a line

Two new event breakpoints in the Breakpoints view: ESP: line sent (Z80 → ESP) and ESP: line received (ESP → Z80). They stop on the exact OUT or IN instruction that completed a line, so you land in the code that sends the command or reads the reply. The condition is text the line must contain, or a regular expression:

CIPSTART            stops when the program sends AT+CIPSTART=…
/^(ERROR|FAIL)$/    stops when the program reads an error
/^\+IPD,\d+:/       stops on the first line of data from the server

Leave the condition empty and it stops on every line.

Good to know

  • The network lives outside the emulator, so Step Back and restoring a saved state do not undo connections.
  • The WiFi (ESP) tab refreshes when the program stops, on Refresh, and continuously with Live turned on.
  • The extension runs on Windows x64.
