Obsah

Úvod

MB Maniax Next Debugger je rozšíření pro Visual Studio Code (dále jen VS Code), které do editoru přidává emulátor ZX Spectra Next a ladicí nástroj (debugger). Program přeložený v sjasmplus se spustí v emulátoru postaveném na jádře JNEXT a vy ho ladíte přímo ve zdrojovém textu: zastavíte ho na řádku, prohlédnete si registry a paměť, krokujete instrukci po instrukci – a vedle kódu přitom vidíte obrazovku emulátoru.

Pokud jste zvyklí na CSpect nebo DeZog, mnoho věcí vám bude povědomých: instrukce BREAK z CSpectu funguje, speciální komentáře WPMEM, LOGPOINT a ASSERTION mají stejnou syntaxi jako v DeZogu. Rozdíl je v tom, že tu nic dalšího neinstalujete ani nespouštíte – emulátor je součástí rozšíření.

Co rozšíření umí

  • Breakpointy ve zdrojáku podle ladicích informací ze sjasmplus (soubor SLD), včetně 8K stránek Nextu – breakpoint v kódu ve stránkované paměti zastaví jen tehdy, když je jeho stránka namapovaná.
  • Podmíněné breakpointy, které nezpomalují – podmínku (A == 5, mem[counter] == 3, nextreg[$50] == 10, FRAME > 100 …) vyhodnocuje přímo emulátor. Návěští ze zdrojáku se v podmínkách píšou přímo.
  • Počty průchodů (3, >= 10, % 4) a logpointy, které místo zastavení vypíšou text s hodnotami.
  • Breakpointy na události stroje: přerušení IM 1 / IM 2, NMI, zápis do NEXTREG, vstup/výstup na port, Copper, DMA, reset.
  • Watchpointy – zastavení při čtení nebo zápisu paměti.
  • Krokování (Step Into / Over / Out), zásobník volání s návěštími, registry a příznaky (dají se měnit), stránky MMU, disassembler, prohlížení a úprava paměti, výrazy v panelu Watch a při najetí myší.
  • Krok zpět (Step Back) – emulátor si pamatuje posledních 10 sekund.
  • Start do NextZXOS – emulátor nabootuje opravdový NextZXOS a ladí se program, který NextZXOS spustí (NextZXOS se na požádání stáhne ze specnext.com).
  • Obrazovka emulátoru v panelu VS Code se zvukem a klávesnicí.
  • Panel Next s pohledy na hardware: sprity, Pattern RAM, palety, vrstvy, Layer 2, tilemapa, program Copperu a všechny registry NEXTREG.
  • Uložené stavy celého stroje a jejich export do souboru.
  • Profiler, který u každého řádku zdrojáku ukáže, kolik T-stavů na něm program strávil.

Požadavky

  • Windows (x64) – balíček rozšíření mbx-next-debugger-win32-x64-0.1.0.vsix obsahuje ladicí server pro 64bitová Windows.
  • Visual Studio Code 1.100 nebo novější.
  • sjasmplus – assembler, kterým program překládáte. Měl by být v cestě (proměnné PATH), aby ho šlo spustit příkazem sjasmplus z terminálu.
  • SD karta ani ROM Nextu nejsou potřeba: rozšíření má vlastní ROM ZX Spectra 48K a program spouští přímo. SD kartu s ROM potřebujete jen pro emulaci jiných strojů než Next (viz ).

Instalace

Rozšíření se dodává jako jeden soubor s příponou .vsix (například mbx-next-debugger-win32-x64-0.1.0.vsix). Je to balíček, který VS Code umí nainstalovat sám – nic nerozbalujte.

Instalace ze souboru .vsix

  1. Spusťte VS Code.
  2. Otevřete panel rozšíření: v úzkém svislém pruhu ikon úplně vlevo (Activity Bar) klikněte na ikonu čtyř čtverečků, nebo stiskněte Ctrl+Shift+X. Vlevo se otevře seznam Extensions.
  3. V záhlaví seznamu (vpravo nahoře nad vyhledávacím polem) klikněte na tři tečky … (Views and More Actions) a vyberte Install from VSIX….
  4. V dialogu najděte soubor .vsix a potvrďte Install. Vpravo dole se objeví zpráva o dokončení instalace.

Stejně to jde i příkazem z palety příkazů: Ctrl+Shift+P, napište vsix a vyberte Extensions: Install from VSIX…. Kdo má rád příkazový řádek, může použít:

code --install-extension mbx-next-debugger-win32-x64-0.1.0.vsix

Aktualizace na novou verzi

Novou verzi nainstalujete úplně stejně – stačí nainstalovat nový soubor .vsix, starý není potřeba předem odinstalovat. Pokud právě běží ladění, nejdřív ho ukončete (Shift+F5). Po instalaci VS Code obvykle nabídne tlačítko pro restart rozšíření; pokud ne, nebo si nejste jistí, že běží nová verze, obnovte okno (další oddíl).

Obnovení okna (Developer: Reload Window)

Po instalaci nebo aktualizaci rozšíření je nejjistější „obnovit okno“ – VS Code tím znovu načte všechna rozšíření, ale otevřené soubory i rozložení oken zůstanou:

  1. Stiskněte Ctrl+Shift+P (nebo F1). Nahoře uprostřed okna se otevře pole palety příkazů.
  2. Napište reload.
  3. Vyberte Developer: Reload Window a stiskněte Enter.

Okno na chvíli zmizí a znovu se vykreslí. Zavřít a znovu spustit celé VS Code funguje také.

Variables – registry a stav stroje

Sekce Variables v postranním panelu Run and Debug ukazuje stav stroje vždy, když program stojí. Má čtyři skupiny:

  • Registry – AF BC DE HL IX IY SP PC šestnáctkově i desítkově ($8000 (32768)), za nimi návěští, na které hodnota ukazuje (start, main_loop+3); dále I, R, režim přerušení IM a IFF1.
  • Příznaky – S Z H P/V N C jako 0 nebo 1.
  • Stínové registry – AF' BC' DE' HL' (ve výchozím stavu sbalené).
  • Stroj (MMU, čas) – Snímek (číslo snímku od startu), T-stavy celkem a osm slotů MMU: MMU0 ($0000) … MMU7 ($E000) s číslem 8K stránky, která je ve slotu namapovaná (stránka 10 ($0A)).

Hodnoty registrů a příznaků se dají měnit ().

Watch

Sekce Watch drží výrazy, které chcete sledovat – například mem[counter] nebo HL. Přidáte je tlačítkem + v záhlaví sekce (objeví se po najetí myší na záhlaví), nebo v editoru označte text, klikněte pravým tlačítkem a vyberte Add to Watch. Hodnoty se přepočítají při každém zastavení. Podrobnosti v .

Call Stack

Sekce Call Stack ukazuje, kde program stojí a kudy se tam dostal: nahoře aktuální místo (jméno nejbližšího návěští), pod ním místa, odkud byly volány podprogramy. Kliknutím na řádek se editor přesune na příslušné místo ve zdrojáku. Místa mimo váš zdroják (ROM, kód bez ladicích informací) jsou šedá a mají u sebe adresu. V záhlaví sekce je i důvod zastavení – například Paused on breakpoint, Paused on step, Paused on BREAK nebo název události.

Breakpoints

Sekce Breakpoints vypisuje všechny breakpointy a logpointy; zaškrtávátkem je dočasně vypnete, dvojklikem přejdete na řádek. Nahoře v seznamu jsou zaškrtávátka událostí stroje tohoto rozšíření (Přerušení (IM 1 / IM 2), NMI, Zápis do NEXTREG …), viz . V záhlaví sekce jsou tlačítka pro vypnutí a smazání všech breakpointů.

První program

V této kapitole přeložíte a spustíte ukázkový program hello ze složky examples/hello. Program mění barvu okraje a počítá v paměti, kolikrát to udělal. Celý postup je stejný jako u vašeho vlastního projektu.

; examples/hello/hello.asm (zkráceno)
        DEVICE ZXSPECTRUMNEXT
        SLDOPT COMMENT WPMEM, LOGPOINT, ASSERTION
        ORG $8000
start:  ei
        ld sp, stack_top
        nextreg $07, 3          ; 28 MHz
        ld a, 0
        ld (counter), a
main_loop:
        call next_colour
        ld b, 25
.wait:  halt
        djnz .wait
        jr main_loop
next_colour:
        ld a, (counter)
        inc a
        and 7
        ld (counter), a
        out ($fe), a
        ret
counter:    db 0
            ds 64
stack_top:
        SAVENEX OPEN "hello.nex", start, stack_top
        SAVENEX CORE 3, 0, 0
        SAVENEX AUTO
        SAVENEX CLOSE

Překlad se ladicími informacemi

Aby ladicí nástroj věděl, který řádek zdrojáku odpovídá které adrese, potřebuje od sjasmplus soubor SLD (Source Level Debugging). sjasmplus ho vytvoří s volbou --sld:

sjasmplus --sld=hello.sld --fullpath hello.asm
  • --sld=hello.sld – zapíše ladicí informace (řádky, adresy, 8K stránky, návěští, klíčová slova z komentářů).
  • --fullpath – zapíše do SLD celé cesty ke zdrojákům, aby rozšíření spolehlivě spárovalo řádky se soubory otevřenými v editoru (i když se zdroják skládá z víc souborů přes INCLUDE).

Výsledný program (hello.nex) vytvoří direktiva SAVENEX ve zdrojáku.

Zkontrolujte, že sjasmplus jde spustit: otevřete terminál (Ctrl+`) a napište sjasmplus --version. Pokud Windows příkaz nezná, přidejte složku se sjasmplus do proměnné PATH (a VS Code pak zavřete a znovu spusťte), nebo v tasks.json napište celou cestu k sjasmplus.exe.

Otevření složky

VS Code pracuje se složkami (workspace), ne s jednotlivými soubory – nastavení ladění a úloh se hledá v podsložce .vscode otevřené složky.

  1. Menu File › Open Folder… (Ctrl+K Ctrl+O) a vyberte složku examples\hello.
  2. Pokud se VS Code zeptá, zda autorům složky důvěřujete (Do you trust the authors…), potvrďte Yes, I trust the authors – jinak by nesměl spouštět úlohy (překlad).
  3. Vlevo v Explorer (Ctrl+Shift+E) klikněte na hello.asm; otevře se v editoru.

Soubor launch.json – jak ladit

Soubor .vscode/launch.json říká, co se má při F5 spustit. Ukázka ho už má:

{
    "version": "0.2.0",
    "configurations": [
        {
            "type": "mbx-next",
            "request": "launch",
            "name": "Ladit hello.nex",
            "program": "${workspaceFolder}/hello.nex",
            "sld": "${workspaceFolder}/hello.sld",
            "stopOnEntry": true,
            "preLaunchTask": "sjasmplus"
        }
    ]
}
  • "type": "mbx-next" – ladí se tímto rozšířením.
  • "name" – jméno, které uvidíte v seznamu vedle zeleného tlačítka ▶.
  • "program" a "sld" – přeložený program a jeho ladicí informace; ${workspaceFolder} je otevřená složka.
  • "stopOnEntry": true – zastavit hned na první instrukci programu.
  • "preLaunchTask": "sjasmplus" – před spuštěním přeložit program úlohou sjasmplus z tasks.json (další oddíl).

Ve vlastním projektu launch.json vytvoříte takto: v panelu Run and Debug klikněte na create a launch.json file a vyberte MB Maniax Next Debugger. Vznikne konfigurace „Ladit na ZX Spectrum Next“ s program.nex a program.sld – přepište jména na svá. Do existujícího launch.json přidáte další konfiguraci tlačítkem Add Configuration… vpravo dole v editoru launch.json a volbou MB Maniax Next Debugger: Next program (sjasmplus) (v českém VS Code program pro Next (sjasmplus)). Všechny atributy popisuje .

Soubor tasks.json – jak překládat

Úloha (task) je příkaz, který VS Code spustí za vás – tady překlad sjasmplus. Soubor .vscode/tasks.json z ukázky:

{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "sjasmplus",
            "type": "shell",
            "command": "sjasmplus",
            "args": ["--sld=hello.sld", "--fullpath", "--lst=hello.lst", "hello.asm"],
            "options": { "cwd": "${workspaceFolder}" },
            "group": { "kind": "build", "isDefault": true },
            "problemMatcher": {
                "owner": "sjasmplus",
                "fileLocation": ["autoDetect", "${workspaceFolder}"],
                "pattern": {
                    "regexp": "^(.*)\\((\\d+)\\):\\s+(error|warning)[^:]*:\\s+(.*)$",
                    "file": 1, "line": 2, "severity": 3, "message": 4
                }
            }
        }
    ]
}
  • "label" – jméno úlohy; na něj odkazuje preLaunchTask v launch.json.
  • "args" – parametry sjasmplus (--lst navíc vytvoří výpis).
  • "group": … "isDefault": true – výchozí úloha překladu: spustíte ji kdykoli zkratkou Ctrl+Shift+B, i bez ladění.
  • "problemMatcher" – chyby a varování sjasmplus se ukážou v záložce Problems a jako podtržení ve zdrojáku.

Spuštění: F5

  1. Stiskněte F5. Ve spodním panelu se otevře Terminal a proběhne překlad. (Pokud překlad selže, VS Code nabídne Debug Anyway nebo Show Errors – podívejte se do Problems.)
  2. Spustí se emulátor a vpravo vedle editoru se otevře panel ZX Spectrum Next s obrazovkou.
  3. Protože ukázka má "stopOnEntry": true, program hned stojí na první instrukci (ei za návěštím start) – řádek je žlutý a vlevo se plní sekce Variables a Call Stack.
  4. Klikněte do okraje vlevo od čísla řádku call next_colour – objeví se červená tečka, breakpoint.
  5. Stiskněte F5 (Continue). Program se rozběhne a zastaví na breakpointu.
  6. Stiskněte F11 (Step Into) – jste uvnitř next_colour. Krokujte dál F11 a sledujte v sekci Variables, jak se mění A; po instrukci out ($fe), a se změní barva okraje na obrazovce emulátoru.
  7. Najeďte myší na slovo counter ve zdrojáku – bublina ukáže jeho adresu a obsah paměti. Do Debug Console (Ctrl+Shift+Y) napište m counter a stiskněte Enter.
  8. Ladění ukončíte Shift+F5 nebo tlačítkem Stop na liště ladění.

Bez launch.json

Pro rychlé vyzkoušení launch.json není nutný: otevřete v editoru soubor .asm (také .a80, .z80 nebo .s) a stiskněte F5. Rozšíření spustí .nex a .sld stejného jména ze stejné složky (k hra.asm tedy hra.nex a hra.sld). Program ale v tomto režimu nepřekládá – přeložte ho předem (Ctrl+Shift+B nebo v terminálu). Pokud se VS Code zeptá, jaký ladicí nástroj použít (Select debugger), vyberte MB Maniax Next Debugger.

Data programu a esxDOS. Bez obrazu SD karty program přes esxDOS vidí složku, ve které leží (načítání dat, uložené pozice). Jinou složku nebo obraz SD karty nastavíte v launch.json atributy esxdosRoot a sdImage.

Program ve složce může soubory číst a zapisovat, mazat (i podle masky, např. *.TMP), přejmenovávat a zkracovat, zakládat a mazat podsložky a nastavovat atribut „jen pro čtení“. Odpovědi a chybové kódy odpovídají NextZXOS. Změny se zapíší na disk hned a krok zpět () je nevrátí.

Ladění

Breakpointy

Breakpoint zastaví program těsně před provedením instrukce na daném řádku.

  • Myší: najeďte v editoru do úzkého okraje vlevo od čísel řádků – objeví se bledě červená tečka. Kliknutím ji „přišpendlíte“, dalším kliknutím breakpoint zrušíte.
  • Klávesou: postavte kurzor na řádek a stiskněte F9 (zapnout / vypnout).
  • Kontextovou nabídkou: pravé tlačítko v okraji vlevo nabízí Add Breakpoint, Add Conditional Breakpoint… a Add Logpoint…; pravé tlačítko na existující tečce nabízí Edit Breakpoint…, Disable Breakpoint a Remove Breakpoint.

Breakpointy můžete dávat i před spuštěním ladění; při startu se pošlou emulátoru. Pokud na řádku není instrukce (komentář, prázdný řádek, samotné návěští), posune se breakpoint na nejbližší další řádek s instrukcí (nejvýš o 20 řádků). Když instrukce ani tam není, zůstane tečka šedá a prázdná (neověřený breakpoint) a bublina u ní řekne proč – například Na řádku ani pod ním není instrukce (podle SLD) nebo Chybí SLD ze sjasmplus (atribut "sld").

Stránkovaná paměť. SLD ze sjasmplus zná u každého řádku i 8K stránku (pokud zdroják používá DEVICE ZXSPECTRUMNEXT). Breakpoint pak zastaví jen tehdy, když je ta stránka v příslušném slotu MMU opravdu namapovaná – kód jiné stránky na stejné adrese ho nespustí. Když je tentýž řádek přeložený do víc stránek, platí breakpoint pro všechny.

Když v okraji tečka vůbec nejde dát (po najetí myší se neobjeví), VS Code nepovažuje soubor za jazyk, pro který rozšíření breakpointy hlásí. Řešení najdete v kapitole .

Run to Cursor a Jump to Cursor

Když stroj stojí, klikněte pravým tlačítkem na řádek zdrojáku:

  • Run to Cursor – program poběží, dokud na tento řádek nedojde (jako jednorázový breakpoint).
  • Jump to Cursor – přesune PC na tento řádek bez provedení kódu mezi. Hodí se k přeskočení kusu kódu nebo k opakování instrukce. Pokud je řádek přeložený na víc adres (víc stránek), VS Code nabídne výběr – položky mají tvar $C000 (stránka 12) a stránky, které právě nejsou namapované, mají poznámku není namapovaná.

Podmíněné breakpointy

Podmíněný breakpoint zastaví, jen když platí podmínka. Podmínku vyhodnocuje přímo emulátor při každém průchodu, takže program nezpomaluje – nemusíte se bát dát ji do smyčky, která běží tisíckrát za snímek.

  1. Pravým tlačítkem klikněte do okraje vlevo od řádku a vyberte Add Conditional Breakpoint… (u existujícího breakpointu Edit Breakpoint…).
  2. Pod řádkem se otevře malé pole. Vlevo v něm je rozbalovací nabídka: nechte Expression.
  3. Napište podmínku a stiskněte Enter. Tečka breakpointu dostane symbol =.

Příklady podmínek:

A == 5
HL > $4000 and not ZF
mem[counter] == 3
mem16[score] >= 1000
nextreg[$50] == 10
FRAME > 100
B == 0 or (IX >= enemies and IX < enemies_end)

Návěští ze zdrojáku (counter, score) se píšou přímo. Úplný jazyk výrazů popisuje kapitola . Chybu v podmínce (překlep, neznámé jméno) pozná emulátor hned: breakpoint zůstane šedý a bublina u něj ukáže chybu. Chyba za běhu (např. dělení nulou) se vypíše do Debug Console.

Počty průchodů

V poli pro úpravu breakpointu vyberte v rozbalovací nabídce Hit Count a zadejte, kolikátý průchod má zastavit:

ZápisZastaví
3 nebo == 3právě při 3. průchodu
>= 10při 10. průchodu a každém dalším
> 10, < 5, <= 5obdobně
% 4při každém 4. průchodu (4., 8., 12. …)

Podmínku a počet průchodů můžete kombinovat – průchody se pak počítají jen tehdy, když podmínka platí. Počítadlo začíná od nuly při každé změně breakpointů.

Logpointy

Logpoint program nezastaví, jen vypíše text do Debug Console – je to ladicí výpis, který nemusíte psát do programu. Pravým tlačítkem v okraji vyberte Add Logpoint… (nebo v poli úpravy breakpointu Log Message) a napište zprávu. Výrazy ve složených závorkách se nahradí hodnotou:

barva {A}, skóre {mem16[score]}
HL={HL:hex} DE={DE:hex} příznaky {F:flags}

Za dvojtečkou může být formát: hex (šestnáctkově), unsigned (výchozí), signed (se znaménkem), char (znak ASCII), bits (dvojkově), flags (příznaky ve tvaru SZHPNC, nenastavené jako -), labels (návěští na adrese). Logpoint má v okraji tvar kosočtverce. Text se vypisuje při každém průchodu, s počtem průchodů jen při splnění počtu.

Některé chyby nesouvisí s konkrétním řádkem: „kdo mi přepisuje registr $50?“, „kdy přišlo přerušení?“. Pro ně má rozšíření v sekci Breakpoints zaškrtávátka událostí. Zaškrtnutím se událost zapne; po najetí myší na položku se vpravo objeví tužka (Edit Condition), kterou zadáte podmínku – bez podmínky zastaví každá událost daného druhu.

Pro porty, u kterých rozhoduje jen dolní bajt (ULA $FE, Kempston $1F …), pište (PORT & $FF) == $FE; plné číslo porovnávejte u 16bitových portů (PORT == $243B).

Watchpointy – zastavení při přístupu do paměti

Watchpoint (ve VS Code „data breakpoint“) zastaví program, když instrukce čte nebo zapisuje zvolenou paměť. Stroj se zastaví hned po instrukci, která přístup provedla.

  • Na registr: v sekci Variables klikněte pravým tlačítkem na BC, DE, HL, IX, IY nebo SP a vyberte Break on Value Change (zápis), Break on Value Read (čtení) nebo Break on Value Access (obojí). Hlídá se bajt, na který registr právě ukazuje – ne registr samotný.
  • Na návěští nebo adresu: přidejte do sekce Watch výraz, který je jen jménem návěští (counter) nebo číslem ($5B00), a na něm pravým tlačítkem zvolte Break on Value Change.
  • Komentářem ve zdrojáku: ; WPMEM () – hodí se pro oblasti delší než bajt a pro watchpointy, které chcete mít pořád.

Watchpointy najdete v sekci Breakpoints a tam je také vypnete nebo smažete. V novějších verzích VS Code nabízí sekce Breakpoints ve svém záhlaví i příkaz Add Data Breakpoint at Address, kde zadáte adresu a délku přímo.

Výrazy ve Watch a při najetí myší

Do sekce Watch můžete napsat libovolný výraz z kapitoly : mem[counter], HL, nextreg[$07], mem16[stack_top - 2], mmu[3]. Výsledek se ukazuje šestnáctkově i desítkově ($03 (3)). Je-li výraz jen jménem návěští, ukáže se jeho adresa a k ní obsah paměti na ní: $8023 (32803) → [$03] [$0003] – v hranatých závorkách bajt a 16bitové slovo.

Když program stojí, stačí v editoru najet myší na registr nebo návěští – bublina ukáže hodnotu a obsah paměti, na kterou ukazuje. Bublina se ukáže jen u slov, která jsou platným výrazem.

Debug Console a výpis paměti

Do vstupního řádku Debug Console (Ctrl+Shift+Y, řádek s > úplně dole) napište výraz a stiskněte Enter; vypíše se jeho hodnota stejně jako ve Watch. Navíc tu funguje příkaz pro výpis paměti:

m adresa
m adresa, délka

Adresa i délka jsou výrazy (číslo, návěští, registr…). Bez délky se vypíše 128 bajtů, nejvýš jde 4096. Každý řádek má adresu, 16 bajtů šestnáctkově, tytéž bajty jako text (netisknutelné jako .) a návěští, které na adrese začíná nebo jí předchází:

> m start, 32
$8000  FB 31 64 80 ED 91 07 03 3E 00 32 23 80 CD 17 80  .1d.....>.2#....  start
$8010  06 19 76 10 FD 18 F6 3A 23 80 3C E6 07 32 23 80  ..v....:#.<..2#.  main_loop+3
> m HL, 16
> m stack_top - 16, 16

Prohlížení a úprava paměti

U 16bitových registrů v sekci Variables se po najetí myší objeví vpravo malá ikona View Binary Data. Otevře paměť od adresy v registru v šestnáctkovém editoru VS Code (rozšíření Hex Editor od Microsoftu – pokud ho nemáte, VS Code nabídne jeho instalaci). V hex editoru lze bajty i přepsat; zápis jde rovnou do paměti emulátoru. Zobrazuje se paměť tak, jak ji vidí procesor (64 KB podle aktuálního mapování MMU).

Disassembler

Když program stojí mimo váš zdroják (v ROM, v kódu bez SLD, v datech), nebo když chcete vidět skutečné instrukce, otevřete disassembler: pravým tlačítkem v editoru zvolte Open Disassembly View, nebo v paletě příkazů Debug: Open Disassembly View. Instrukce mají u sebe návěští ze SLD a řádky zdrojáku. I v disassembleru lze klikem vlevo od adresy dát breakpoint a krokovat po instrukcích. Bez souboru SLD se ladí jen tady.

Úprava registrů a příznaků

V sekci Variables dvakrát klikněte na hodnotu registru (nebo pravým tlačítkem Set Value), napište novou hodnotu a stiskněte Enter. Čísla lze psát jako $FF, 0xFF, #FF, FFh, 255 nebo dvojkově %1010. Příznaky (S Z H P/V N C) mají hodnotu 0 nebo 1. Chcete-li přesunout PC na jiný řádek, je pohodlnější Jump to Cursor () – editor se přesune s ním.

Klíčová slova v komentářích sjasmplus

Watchpointy, logpointy a aserce můžete zapsat přímo do zdrojáku jako speciální komentáře (stejná syntaxe jako v DeZogu). Výhoda: jsou součástí kódu, neztratí se, a fungují v každém ladicím sezení bez klikání.

SLDOPT – zapnutí v sjasmplus

sjasmplus zapisuje tyto komentáře do souboru SLD jen tehdy, když je ve zdrojáku (nejlépe na začátku) řádek:

    SLDOPT COMMENT WPMEM, LOGPOINT, ASSERTION

Stačí uvést ta slova, která používáte. sjasmplus hledá slovo kdekoli v komentáři a rozlišuje velikost písmen (piště je velkými písmeny); blokové komentáře /* */ do SLD nezapisuje. Komentář na samostatném řádku platí pro nejbližší následující instrukci, komentář za instrukcí pro instrukci na tomtéž řádku. U makra se komentář vztahuje k místu, odkud je makro voláno.

WPMEM – watchpoint

; WPMEM [adresa [, délka [, přístup [, podmínka]]]]
  • adresa – výraz; bez ní adresa řádku, na kterém komentář je (typicky návěští dat).
  • délka – počet hlídaných bajtů, výchozí 1.
  • přístup – r čtení, w zápis, rw obojí (výchozí).
  • podmínka – nepovinná; zastaví, jen když platí (lze použít ADDR a VALUE).
score:  dw 0            ; WPMEM            – hlídá 1 bajt na „score“ (čtení i zápis)
buffer: ds 16           ; WPMEM buffer,16,w – zastaví při zápisu do 16 bajtů
lives:  db 3            ; WPMEM lives,1,w,VALUE == 0 – zastaví, když se zapíše nula
        ; WPMEM $4000, $1800, w   – zápis kamkoli do bitmapy ULA

Po zastavení je v záhlaví Call Stack důvod WPMEM a v Debug Console řádek s rozsahem adres a místem komentáře, například WPMEM $8030–$803F (game.asm:120) – WPMEM buffer,16,w.

LOGPOINT – ladicí výpis

; LOGPOINT [SKUPINA] text ${výraz} text ${výraz:formát}

Při každém průchodu vypíše text do Debug Console; ${…} nahradí hodnotou výrazu. Formáty jsou stejné jako u logpointů ve VS Code: hex, unsigned, signed, char, bits, flags, labels. Nepovinná skupina v hranatých závorkách hned za slovem se vypíše na začátek řádku ([AI] …). U výpisu v Debug Console je odkaz na řádek zdrojáku, kliknutím na něj se tam přesunete.

        ld a,(hl)
        ; LOGPOINT [MAP] přečteno ${A:hex} z ${HL:hex}
        ld (de),a

ASSERTION – aserce

; ASSERTION výraz

Zastaví program, když výraz neplatí (je nula). Prázdná ASSERTION zastaví vždy. V záhlaví Call Stack je důvod aserce s popisem ASSERTION neplatí: A < 10; stejný text s místem ve zdrojáku se vypíše do Debug Console.

        cp 10           ; ASSERTION A < 10 – zastaví, když výraz neplatí
        ; ASSERTION SP > stack_bottom and SP <= stack_top
        ret

Kdy se klíčová slova vyhodnocují

LOGPOINT a ASSERTION jsou breakpointy na adrese svého řádku – vyhodnocují se před provedením instrukce na tom řádku. V příkladu ld a,(hl) ; LOGPOINT … ${A} by se tedy vypsalo A ještě před načtením. Chcete-li vidět výsledek instrukce, dejte komentář na samostatný řádek pod ni (platí pak pro další instrukci), jako v příkladu výše.

Vypnutí

Každý druh jde vypnout v launch.json, aniž byste měnili zdroják: "wpmem": false, "logpoints": false, "assertions": false (výchozí hodnota všech je true).

BREAK z CSpectu

Instrukce BREAK z emulátoru CSpect zastaví program jako breakpoint – hodí se tam, kde je jednodušší napsat zastavení do kódu než klikat.

  • sjasmplus s volbou --zxnext=cspect překládá BREAK jako FD 00. Funguje i starší CSpect DD 01 a ED FF ze ZEsarUX.
  • Stroj se zastaví hned za instrukcí (PC = adresa BREAK + 2): žlutý řádek je na instrukci za BREAK, popis v Call Stack uvádí adresu samotného BREAK.

V záhlaví Call Stack je důvod BREAK s popisem Zastaveno na BREAK na $8003. Pokračujete normálně (F5, kroky). Zastavování vypnete v launch.json: "magicBreakpoint": false.

Na skutečném Nextu se FD 00 provede jako NOP, ale DD 01 jako LD BC,nn a „spolkne“ další dva bajty. DD 01 proto nenechávejte ve výsledném programu. Vypnutý magicBreakpoint se k DD 01 chová stejně jako skutečný Next.

Sprity

Lišta: Jen viditelné skryje sprity s vypnutým bitem viditelnosti (zapnuto ve výchozím stavu); Náhled s transformací kreslí náhledy se zrcadlením a rotací tak, jak vypadají na obrazovce. Vpravo je stav: průhledná barva (Průhledná NR $4B = $E3) a která paleta spritů se používá.

Souhrnný řádek: počet viditelných spritů (Viditelných: 12 / 128), zda jsou sprity zapnuté (Sprity vypnuty (NR $15 b0) je zvýrazněné jako varování), zda se kreslí přes okraj (přes okraj) a zda je sprite 0 nahoře (sprite 0 nahoře), a ořezové okno spritů – syrové hodnoty NR $19 i výsledné okno v souřadnicích obrazovky.

Pattern RAM

Celá paměť vzorů spritů (16 KB) jako mřížka. Lišta:

  • Formát vzorů – 8bit · 64 vzorů nebo 4bit · 128 vzorů.
  • Paleta spritů – Aktivní paleta (podle NR $43 bit 3, v závorce která), nebo pevně Sprity 1. / Sprity 2.
  • Offset 0–15 – paletový offset pro náhled (u 4bitových vzorů horní nibble indexu, u 8bitových se přičte k hornímu nibblu).
  • Zvětšení mřížky a Průhlednost – pixely s hodnotou NR $4B kreslit průhledně (šachovnicí).

Bublina nad vzorem ukazuje jeho číslo a adresu a které sprity ho používají – zvlášť viditelné a neviditelné. Klikněte na vzor: pod mřížkou se ukáže zvětšený detail s adresami, seznamem spritů, které vzor používají, a po najetí myší na pixel jeho souřadnice, hodnota (u 4bitových i který nibble), index v paletě a barva v RGB333 i RGB888.

Palety

Všech osm palet Nextu, každá jako mřížka 16 × 16: ULA 1. a 2., Layer 2 1. a 2., Sprity 1. a 2., Tilemapa 1. a 2. Index barvy roste po řádcích zleva doprava (první řádek 0–15).

  • Štítek aktivní – tuto paletu používá vykreslování.
  • Štítek zápis – sem právě míří zápisy přes NR $41/$44 (podle NR $43 bity 6:4).
  • Křížek × označuje průhlednou barvu: u ULA, Layer 2 a tilemapy barvu NR $14, u spritů index NR $4B. Legenda pod paletou to vypisuje a u ULA popisuje, které indexy jsou ink, paper a okraj (standardní ULA nebo ULANext s formátem z NR $42).
  • Ztlumit nepoužité (ULA) – v paletách ULA ztlumí položky, které aktuální režim nepoužívá.

Řádek vedle přepínače ukazuje registry NR $43 · $42 · $14 · $4B · $6B. Po najetí myší na barvu se nahoře vypíše: paleta, index (hex i dec), RGB333 a jednotlivé složky R G B (0–7), 8bitová hodnota RRRGGGBB, barva jako #rrggbb a role barvy (ink, paper, okraj, průhledná, nepoužitá…).

Vrstvy

Rozloží obraz na vrstvy, ze kterých ho Next skládá. V nabídce vlevo zvolíte, co vidět: Složený obraz, ULA, ULA stínová, Layer 2, Layer 2 stínová, Sprity, Tilemapa, Pozadí; vedle je zvětšení 1× / 2×. Zaškrtávátko vše vedle sebe ukáže náhledy všech vrstev najednou – kliknutím na náhled se zobrazí ve velkém.

Šachovnice znamená, že vrstva v tom místě nic nekreslí (průhledné). Po najetí myší se pod obrazem vypíše souřadnice (x, y v prostoru 320 × 256 a sloupec v 640 bodech širokém obrazu) a barva pixelu (#rrggbb a RGB333). Vrstvy se kreslí pro celý snímek s registry přehranými po řádcích, takže se projeví i rozdělení obrazu rastrem nebo Copperem.

Pod obrazem jsou tři bloky informací:

  • Pořadí shora (NR $15, režim SLU, LSU …) – seznam vrstev od nejvyšší po nejnižší s pozadím (NR $4A) na konci. U režimů míchání barev (L+U sčítání / odečítání) je popsané, jak se ULA a tilemapa míchají s Layer 2. Vypnuté vrstvy jsou přeškrtnuté. Poznámka připomíná, že pixel Layer 2 s prioritním bitem palety (NR $44 b7) jde vždy navrch.
  • Vrstvy – zda jsou zapnuté ULA (NR $68 b7), LoRes, Layer 2 (NR $69 b7 / port $123B), sprity (i v okraji, sprite 0 navrchu) a tilemapa (vždy nad ULA, nebo podle atributu).
  • Ořezová okna – okna Layer 2, spritů, ULA a tilemapy.

Zastaví-li se stroj uprostřed snímku, řádky pod paprskem jsou nakreslené s aktuálním stavem registrů – na obrazovce emulátoru je tam ještě předchozí snímek, proto se mohou lišit.

Layer 2

Celý obsah Layer 2 z paměti – nejen to, co je vidět. Přepínač vlevo volí banku: Aktivní (NR $12) nebo Stínová (NR $13); dále zvětšení a viditelná část: čárkovaný obdélník ukazuje, co je po posunu (scroll) a ořezu na obrazovce, kroužek levý horní roh obrazovky.

Informační řádky nahoře: režim (NR $70 – 256 × 192, 8 bpp, 320 × 256, 8 bpp (po sloupcích) nebo 640 × 256, 4 bpp (po sloupcích)) a zda je Layer 2 zapnutá; banka a její stránky; scroll X/Y (NR $16/$71, $17) a ořez NR $18; paleta (první/druhá podle NR $43 b2), offset palety (NR $70 b3:0) a průhledná barva NR $14. Po najetí myší se vypíše banka a posun (i 8K stránka), bajt na tom místě (u 4bpp který nibble), index barvy a případně (průhledná).

Tilemapa

Nahoře celá mapa (40 × 32 nebo 80 × 32 dlaždic) se zvětšením 1× / 2× a volbou viditelná část (čárkovaný výřez po scrollu a ořezu, kroužek = levý horní roh obrazovky). Informační řádky: režim (NR $6B – počet sloupců, 4 bpp nebo textový 1 bpp, 256/512 dlaždic, s atributy nebo bez – pak platí výchozí atribut NR $6C), zda je tilemapa zapnutá a zda je vždy nad ULA; adresy mapy (NR $6E) a definic (NR $6F) v bance 5 nebo 7; scroll (NR $2F/$30, $31) a ořez NR $1B; paleta tilemapy (NR $6B b4) a průhledný index NR $4C (v textovém režimu barva NR $14).

Najeďte myší na dlaždici v mapě: vypíše se její sloupec a řádek, index dlaždice, atribut rozepsaný na paletu, zrcadlení, rotaci a prioritu vůči ULA, a adresa záznamu v mapě i definice. Dlaždice se zároveň orámuje v definicích pod mapou a zvýrazní v obrazovce emulátoru na místě, kde po scrollu leží.

Definice dlaždic pod mapou: všechny definované dlaždice v mřížce po 16; nad nimi offset palety pro náhled (0–15) a zvětšení 2× – 4×. Po najetí myší se ukáže číslo dlaždice a adresa její definice.

NEXTREG

Tabulka registrů Nextu se jménem, skupinou, přístupem, hodnotou šestnáctkově, desítkově a dvojkově a s rozpisem bitů do pojmenovaných polí (například u NR $07 rychlost procesoru, u NR $15 pořadí vrstev). Lišta:

  • Hledat (číslo, jméno, bit)… – filtruje podle čísla registru, jména nebo názvu bitového pole.
  • Všechny skupiny – omezí tabulku na skupinu: Stroj, Video, Layer 2, Sprity, Tilemapa, Copper, Palety, MMU, Zvuk, Ostatní.
  • všech 256 – ukáže i čísla, která Next nedefinuje.
  • jen změněné – jen registry změněné od minulého obnovení.

Registry, které se od minulého obnovení změnily, mají podbarvený řádek a změněné bity jsou zvýrazněné – stačí krokovat a dívat se, co se mění. Počet je vpravo (zobrazeno 84 · změněno 3). Sloupec Přístup: č/z čtení i zápis, č jen čtení, z jen zápis – u registrů jen pro zápis je zobrazená hodnota poslední zápis (nebo 0, pokud ji emulátor neuchovává); hvězdička a bublina upozorňují, když se čtená hodnota liší od zapsané.

Uložené stavy

Uložený stav je snímek celého stroje – paměti, registrů, hardwaru. Hodí se, když se chcete opakovaně vracet do stejného místa hry (před souboj s bossem, před chybou) bez toho, abyste se tam pokaždé „dohrávali“.

Uložení a obnovení

  • MB Maniax: Save State… (Uložit stav…) – tlačítko s ikonou diskety na liště ladění nebo příkaz z palety. Nahoře se otevře pole Uložit stav emulátoru; zadejte jméno a stiskněte Enter. Stejné jméno přepíše starší stav (rozšíření se nejdřív zeptá).
  • MB Maniax: Restore State… (Obnovit stav…) – tlačítko s ikonou hodin. Ze seznamu vyberte stav; stroj se do něj vrátí a zůstane stát (v Call Stack je důvod obnovení stavu). Pokračujte F5.

Stavy platí pro aktuální ladicí sezení (do Stop) – přežijí i Restart. V jednom sezení jich může být nejvýš 8. Obnovení nemění breakpointy ani profiler.

Stav se ukládá na konci snímku

Emulátor umí uložit stav jen na hranici snímku. Běžící program je na ní vždy, takže uložení za běhu proběhne hned. Stojí-li stroj uprostřed snímku (breakpoint, krok), rozšíření se zeptá: Stroj stojí uprostřed snímku. Stav lze uložit jen na konci snímku. Doběhnout na konec aktuálního snímku a uložit stav tam? Tlačítkem Doběhnout na konec snímku a uložit program doběhne na konec snímku (breakpointy se při tom ignorují), zastaví se (důvod hranice snímku) a stav se uloží.

Export a import do souboru

MB Maniax: Export State to File… (Exportovat stav do souboru…) uloží aktuální stav do souboru .mbxstate, MB Maniax: Import State from File… (Importovat stav ze souboru…) ho načte – i v jiném ladicím sezení. Oba příkazy jsou jen v paletě příkazů a jen během ladění. Soubor jde načíst jen ve stejné verzi rozšíření a pro stejný typ stroje; po aktualizaci rozšíření staré soubory nepůjdou načíst.

Profiler

Profiler měří, kde program tráví čas. Sčítá T-stavy (takty procesoru) strávené na každé instrukci a výsledek ukáže přímo ve zdrojáku: u každého řádku, kolik stál, a barvou, jak je drahý vůči ostatním.

Spuštění

  1. Během ladění klikněte na liště ladění na tlačítko Start Profiler (ikona „tepu“), nebo v paletě příkazů MB Maniax: Start Profiler (Spustit profiler). Vlevo dole ve stavovém řádku se objeví Profiler.
  2. Nechte program běžet tu část, kterou chcete měřit (například pár sekund hry).
  3. Zastavte program (F6, breakpoint). Při každém zastavení se výsledek ukáže v otevřených editorech a ve stavovém řádku přibude součet: Profiler: 3 512 000 T.

Jak číst výsledky

  • Šedý text za koncem řádku, např. 1 234 T · 12,3 %: řádek spotřeboval 1 234 T-stavů, což je 12,3 % všech T-stavů za dobu měření (včetně času mimo váš zdroják). Po najetí myší na řádek to bublina zopakuje.
  • Pozadí řádku od světle žluté po červenou: cena řádku vůči nejdražšímu řádku (8 stupňů). Nejdražší řádky jsou nejvíc červené – na ně se dívejte nejdřív.
  • Značky v posuvníku vpravo (přehled souboru): stejné barvy, takže drahá místa najdete i v dlouhém souboru bez listování.

Řádek, který se provádí mnohokrát, je drahý, i když je instrukce sama rychlá – profiler ukazuje celkový čas, ne čas jednoho průchodu. Započítává se vše, co procesor provede: i čekání v HALT (každé opakování) a přijetí přerušení (připíše se instrukci, před kterou přišlo). Nepočítá se doba, kdy procesor stojí kvůli DMA, ani doba pauzy. Instrukce v makru se připíšou řádku, odkud je makro voláno.

Nejdražší funkce

MB Maniax: Show Profiler Results (Zobrazit výsledky profileru) – z palety příkazů, nebo kliknutím na Profiler ve stavovém řádku – otevře seznam Nejdražší funkce seřazený od nejdražší. Funkce je úsek kódu od globálního návěští po další globální návěští (lokální návěští s tečkou patří ke svému nadřazenému). U každé je součet T-stavů s podílem a soubor s řádkem; výběrem se na ni přesunete. Položka Mimo zdroják (ROM, kód bez SLD) na konci sčítá čas strávený mimo váš zdroják.

Živé obnovování, zastavení, vynulování

  • MB Maniax: Toggle Live Profiler Updates (Přepnout živé obnovování profileru) – výsledky se obnovují i za běhu, každou sekundu. Hodí se, když chcete vidět, jak se čísla mění během hraní.
  • MB Maniax: Stop Profiler (Zastavit profiler, tlačítko na liště ladění) – měření skončí, poslední výsledky zůstanou v editoru (i po konci ladění). Objeví se hláška s naměřeným součtem a tlačítkem Zobrazit výsledky; součet zůstane i ve stavovém řádku dole a kliknutím na něj seznam nejdražších funkcí otevřete kdykoli znovu.
  • MB Maniax: Clear Profiler Data (Vynulovat profiler) – začne počítat od nuly a obarvení odstraní. Profiler přitom běží dál.

Tipy

  • Měřte jen to, co vás zajímá: spusťte program, dojeďte na místo, dejte Clear Profiler Data, nechte běžet a zastavte.
  • Hlavní smyčka hry čekající na HALT ukáže velké číslo právě u HALT – to je volný čas snímku, ne chyba. Čím menší podíl má HALT, tím méně rezervy máte.
  • Restart a nové nahrání programu čítače vynulují; profiler zůstane zapnutý.
  • Profiler počítá podle fyzické adresy (stránka + posun), takže kód ve stránkách se nepomíchá, i když běží na stejné adrese.

Krok zpět

Krok zpět (Step Back) vrátí stroj o instrukci zpět – i několikrát po sobě. Emulátor si k tomu pamatuje posledních 10 sekund běhu. Je to užitečné, když se program zastaví na chybě a vy chcete vidět, jak se do ní dostal.

Zapnutí

Krok zpět je ve výchozím stavu vypnutý, protože záznam stopy instrukcí emulaci zpomaluje – u Nextu na 28 MHz asi o čtvrtinu. Zapněte ho v launch.json:

"rewind": true

a spusťte ladění znovu. Bez toho tlačítko Step Back ohlásí Krok zpět je vypnutý – zapněte "rewind": true v launch.json (emulace pak běží pomaleji).

Použití

Když program stojí, klikněte na liště ladění na Step Back (šipka s obloukem dozadu). Každé kliknutí vrátí jednu instrukci; registry, paměť i obraz odpovídají stavu před ní. Pak můžete znovu krokovat vpřed. Tlačítko Reverse (zpětný běh až k breakpointu) zatím není – ohlásí Zpětný běh zatím není – použijte Step Back.

Pokud vám zpomalení vadí jen občas, mějte v launch.json dvě konfigurace – jednu s "rewind": true a jednu bez – a vybírejte mezi nimi v seznamu vedle zeleného tlačítka v Run and Debug.

Start do NextZXOS

Normálně se program nahraje přímo do paměti emulátoru, bez operačního systému. Se startem do NextZXOS emulátor nabootuje opravdový NextZXOS z SD karty a program spustí NextZXOS – stejně jako na skutečném Nextu. Program pak má k dispozici všechno, co mu NextZXOS dává: jeho esxDOS, Browser, BASIC, ovladače. Hodí se to pro programy, které NextZXOS potřebují, a pro vyzkoušení, jak se program chová po spuštění z Browseru.

NextZXOS není součástí debuggeru. Distribuce System/Next (NextZXOS © Garry Lancaster, firmware, ROM) patří svým autorům a šíří se pod vlastní licencí („The Next License“). Debugger ji proto nepřibaluje: stáhne oficiální distribuci pro emulátory ze specnext.com až na váš pokyn a po vašem souhlasu s licencí a uloží ji jen do dat rozšíření na vašem počítači.

Stažení NextZXOS

Spusťte příkaz MB Maniax: Download NextZXOS (česky Stáhnout NextZXOS) z palety (Ctrl+Shift+P). Stejnou nabídku dostanete při prvním startu do NextZXOS, pokud ještě stažený není.

  1. Otevře se text licence distribuce, načtený z oficiálního repozitáře distribuce. Přečtěte ho a klikněte na Souhlasím – stáhnout. Souhlas se pamatuje; zeptá se znovu, jen když se text licence změní.
  2. Stáhne se zip s distribucí (asi 50 MB). Debugger zkontroluje jeho velikost a otisk SHA-256; soubor, který nesouhlasí, smaže.
  3. Ze zipu připraví obraz SD karty (asi 1 GB) a z něj pracovní kartu. Uvítací program NextZXOS, který čeká na klávesu, na ní vypne (totéž jako jeho volba D).

Všechno leží v datech rozšíření (globalStorage, složka nextzxos), dohromady asi 2 GB. Výchozí je System/Next 24.11 (NextZXOS 2.09). Novější distribuci nastavíte v nastavení mbxNext.nextzxos.url, mbxNext.nextzxos.sha256 a mbxNext.nextzxos.size (viz ).

Konfigurace v launch.json

Ke konfiguraci přidejte "boot": "nextzxos" (nebo vložte předpřipravenou konfiguraci MB Maniax: Start do NextZXOS tlačítkem Add Configuration…):

{
    "type": "mbx-next",
    "request": "launch",
    "name": "Ladit přes NextZXOS",
    "program": "${workspaceFolder}/build/game.nex",
    "sld": "${workspaceFolder}/build/game.sld",
    "esxdosRoot": "${workspaceFolder}/data",
    "boot": "nextzxos"

Po F5:

  1. Program a obsah složky esxdosRoot (bez ní složka, ve které program leží) se nahrají na kartu do /MBX/<jméno programu> – tady /MBX/game. Skryté soubory a složky (.git …) se vynechají; jména musí být v ASCII.
  2. Do c:/nextzxos/autoexec.bas se zapíše krátký program, který přejde do té složky a program spustí. Váš vlastní autoexec.bas na kartě se odloží a po sezení vrátí.
  3. Emulátor nabootuje NextZXOS (na obrazovce emulátoru uvidíte celý start, trvá asi 8 sekund) a NextZXOS program spustí. V Debug Console je NextZXOS startuje z SD karty ….
  4. Debugger zastaví na první instrukci programu a teprve pak nastaví breakpointy – dřív by se mohly trefit do kódu NextZXOS na stejných adresách. Dál se ladí jako obvykle.

Řešení problémů

Breakpoint nejde dát – po najetí myší do okraje se neobjeví červená tečka

VS Code povoluje breakpointy jen v souborech, jejichž jazyk nějaký ladicí nástroj podporuje. Toto rozšíření je hlásí pro jazyky z80-asm, asm-collection, z80-macroasm, asm, asm-x86-nasm, nasm, masm, c6510 a plaintext (prostý text). Pokud máte nainstalované rozšíření pro jiný assembler, které si .asm přivlastní pod jiným jazykem, breakpointy nepůjdou.

  1. Podívejte se vpravo dole do stavového řádku – je tam jazyk otevřeného souboru (např. Plain Text, Z80 Assembly, ARM…).
  2. Klikněte na něj. Nahoře se otevře výběr jazyka; zvolte Configure File Association for '.asm'… a vyberte jazyk Z80 (podle nainstalovaného rozšíření např. Z80 Assembly, Z80 Macro-Assembler), nebo Plain Text.

VS Code tím zapíše do nastavení files.associations. Totéž můžete napsat ručně (Preferences: Open User Settings (JSON) z palety příkazů):

"files.associations": {
    "*.asm": "z80-macroasm",
    "*.i.asm": "z80-macroasm"
}

Hodnota musí být identifikátor jazyka ze seznamu výše, který máte k dispozici (plaintext je vždy).

Breakpoint je šedý a prázdný

Breakpoint není ověřený. Najeďte na něj myší – bublina řekne proč: Chybí SLD ze sjasmplus (atribut "sld") → doplňte "sld" do launch.json; Na řádku ani pod ním není instrukce (podle SLD) → řádek není ve SLD (je to komentář, data, nebo soubor nebyl přeložen s tímto SLD); chyba podmínky → opravte podmínku ().

Program se na breakpointu nezastaví
  • Chybí SLD nebo je starý: přeložte s --sld=… --fullpath a zkontrolujte, že launch.json ukazuje na stejný soubor. Při startu bez SLD rozšíření ukáže upozornění Chybí "sld" v launch.json… nebo SLD nejde načíst….
  • Cesty v SLD nesedí se soubory v editoru: použijte --fullpath, nebo nastavte sourceRoot.
  • Překládáte jinou kopii souboru, než máte otevřenou v editoru (jiná složka).
  • Kód ve stránkované paměti: breakpoint zastaví jen při namapované stránce (). Zkontrolujte v Variables › Stroj (MMU, čas), která stránka je ve slotu.
  • Breakpoint je vypnutý (nezaškrtnutý v sekci Breakpoints), nebo jsou vypnuté všechny (tlačítko Toggle Active Breakpoints v záhlaví sekce).
  • Program se po změně nepřeložil – preLaunchTask v launch.json chybí, nebo překlad selhal (záložka Problems, Terminal).
Ladění se nespustí
  • Program nenalezen: … – cesta v "program" je špatně, nebo program ještě nebyl přeložen.
  • Ladicí server nenalezen (…) – rozšíření je poškozené nebo je špatně nastavené mbxNext.serverPath; nastavení vymažte, případně rozšíření přeinstalujte.
  • Ladicí server neodpovídá / Ladicí server skončil při startu – zkuste ladění spustit znovu; podrobnosti (výpis serveru) bývají v Debug Console. Spuštění serveru může blokovat i antivirus.
  • Úloha sjasmplus nejde spustit – sjasmplus není v PATH ().
Trhaný zvuk, pomalá emulace
  • Podívejte se na Běží · N snímků/s v liště obrazovky. Pod 50 počítač emulaci nestíhá.
  • Vypněte krok zpět ("rewind": false) – stopa instrukcí zpomaluje asi o čtvrtinu.
  • Vypněte Živě v panelu Next a živé obnovování profileru; zavřete panel Next, když ho nepotřebujete.
  • Logpointy, které se vypisují tisíckrát za sekundu, zpomalí výpis do Debug Console – použijte počet průchodů (% 50) nebo podmínku.
  • Panel s obrazovkou překresluje jen tehdy, když je vidět; schovaný za jinou záložkou nic nestojí.
Panel s obrazovkou nebo panel Next zmizel

Panely jsou záložky editoru: zkuste je najít v jiné skupině záložek, nebo je otevřete znovu – MB Maniax Next: Show Emulator Screen a MB Maniax: Next Panel (Sprites, Palettes, …).

Klávesnice nefunguje v emulátoru / zkratky nefungují ve VS Code

Klávesy jdou do emulátoru jen tehdy, když má fokus obraz (klikněte do něj). Naopak zkratky VS Code (F5, F10) fungují, jen když fokus obraz nemá – klikněte do editoru.

Zvuk nehraje

Klikněte do obrazu nebo na tlačítko 🔇 – zvuk se smí zapnout až po kliknutí. Zkontrolujte, že program běží (v pauze je ticho) a že je ikona 🔊.

Rozšíření mluví jiným jazykem, než chci

Nastavte mbxNext.language () a spusťte ladění znovu. Názvy příkazů a popisy v nastavení se řídí jazykem VS Code (příkaz Configure Display Language), ne tímto nastavením.

Po aktualizaci se pořád chová stará verze

Ukončete ladění a obnovte okno: Ctrl+Shift+P → Developer: Reload Window ().

Uložený stav ze souboru nejde importovat

Soubor .mbxstate jde načíst jen ve stejné verzi rozšíření a pro stejný typ stroje (machine).
